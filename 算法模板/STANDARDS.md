# 项目规范和最佳实践

## 📝 文件命名规范

### Python 文件
- `solution.py` - 主要实现文件
- `solution_v2.py` - 优化版本或其他实现方式
- `test.py` - 单元测试
- `benchmark.py` - 性能测试（可选）

### C++ 文件
- `solution.cpp` - 主要实现
- `solution.h` - 头文件（如需要）
- `test.cpp` - 测试代码

### 文档文件
- `README.md` - 算法详细说明
- `notes.md` - 学习笔记（可选）
- `complexity.md` - 复杂度分析（可选）

## 🚀 版本管理建议

### Git 提交规范
```
# 格式
[类型] [模块] - [简短描述]

# 示例
[新增] 01_数据结构/链表 - 完成链表的插入和删除
[优化] 02_排序算法/快速排序 - 优化partition函数
[修复] 04_动态规划/背包 - 修复边界情况bug
[文档] README - 更新学习计划

# 类型选择
- 新增 (Add)：新算法或新功能
- 优化 (Improve)：代码优化或性能提升  
- 修复 (Fix)：bug修复
- 文档 (Docs)：文档更新
- 重构 (Refactor)：代码重构
```

## 📞 常见问题

### Q: 应该先写Python还是C++？
A: 建议先Python(快速验证逻辑)，再C++(性能优化)

### Q: 每个算法要花多长时间？
A: 一般3-5天（学习1天，实现1-2天，练习1-2天）

### Q: 代码注释要多详细？
A: 中等详度，关键步骤说明，不要注释每一行

### Q: 如何学习复杂度分析？
A: 学习Big-O表示法，多做练习，参考教材示例
