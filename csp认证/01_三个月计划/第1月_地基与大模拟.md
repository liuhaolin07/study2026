## W3（10-05 ~ 10-11）T3 大模拟入门 ★本月最重要

### 目的

T3 是 CSP 的分水岭。这周要建立**大模拟的标准工作流**，而不是靠感觉写。

### 大模拟四步法（背下来，每题都这么走）

> 下面是**入门版**。完整版（含失分三大原因、重写策略、代码组织方式、做完必答的 5 个问题）见
> [`../02_知识清单/10_其他与应试.md`](../02_知识清单/10_其他与应试.md) §10.1，两处内容一致。

#### 第 1 步：拆规则

题面读 **3 遍**，把每条规则编号写在草稿纸上：

```
R1: 输入 n 个操作，每个操作是 "insert x" / "delete x" / "query x"
R2: insert 时若 x 已存在，忽略
R3: delete 时若 x 不存在，输出 "error"
R4: 所有操作按输入顺序执行，但同一时刻的 delete 优先于 insert
R5: 输出总量可能很大，需要 ...
```

**圈出所有限定词**：「若」「则」「同时」「不超过」「恰好」「至少」「保证」「优先」。
CSP 的坑 90% 藏在这些词里，尤其是 **R4 这类"同时发生怎么处理"**。

#### 第 2 步：定状态

先把所有需要维护的量列出来，再选容器。**不要边想边写代码。**

```cpp
struct State {
    // 列出所有状态量，每个都写注释说明含义和取值范围
};
```

容器选型速查：

| 需求 | 选择 |
|---|---|
| 按 key 快速查 + **需要有序遍历** | `std::map` / `std::set` |
| 按 key 快速查 + **不需要顺序** | `unordered_map` / `unordered_set`（更快） |
| 动态取最值 | `priority_queue`（**默认是大根堆**，小根堆要 `greater<>`） |
| 顺序处理 + 头部弹出 | `queue` / `deque` |
| 需要撤销/回退 | `stack` 或 `vector` 存历史 |
| 区间查询/修改 | 树状数组 / 线段树（T3 少见，T4 常见） |

#### 第 3 步：排顺序

明确**事件的时间轴**：

- 事件是否有先后？→ 按时间 `sort`
- 同一时刻多个事件？→ **题目一定给了优先级规则，回去找**
- `sort` 多关键字排序时，比较器要**严格按题目给的优先级顺序**写

#### 第 4 步：分阶段实现 + 逐样例验证

**每实现一条规则，就用样例验证一次。** 绝对不要 300 行写完再跑——那样调试成本是指数级的。

### 大模拟失分三大原因

| 原因 | 症状 | 对策 |
|---|---|---|
| **题意理解偏差** | 样例都过不了 | 题面读 3 遍，圈限定词；自己复述一遍题意 |
| **边界没处理** | 样例过，测试点丢 10~30 分 | 主动造极端样例：空集、n=1、最大值、全相同、重复操作 |
| **数据类型溢出** | 小数据对，大数据全错 | **默认全用 `long long`**，尤其求和/乘积/计数 |

5. **记录**：全程填 [`../05_模考与复盘/模考记录模板.md`](../05_模考与复盘/模考记录模板.md)，包括"当时在想什么"

### 模考① 不达标（< 220）怎么办

不要慌，也不要加量。按丢分题号定位：

| 丢分位置 | 诊断 | 处理 |
|---|---|---|
| T1/T2 丢分 | **最严重**，这是不该丢的分 | W5 每天开头 30 min 加练 T1/T2 限时，直到连续 5 道满分 |
| T3 < 40 分 | 大模拟流程没建立 | W5 把 ACM 主线砍半，每天 1 道 T3 |
| T4/T5 = 0 分 | **没有"先交暴力"的习惯** | 强制训练：任何题读完 10 min 内必须有暴力提交，否则不算做完 |
| 时间不够用 | 前 3 题太慢 | 严格卡时间，到点必须切下一题 |
