## 一、数据范围反推复杂度 ★最重要的反射

**看到 n 的范围，就应该知道能用什么算法。** 练到条件反射。

| 数据范围 n | 可行复杂度 | 约等于 | 典型算法 |
|---|---|---|---|
| n ≤ 10 | `O(n!)` / `O(n^n)` | 3×10⁶ | 全排列枚举、暴力 DFS |
| n ≤ 20 | `O(2^n · n)` | 2×10⁷ | **状态压缩枚举**、记忆化搜索、Meet in the Middle |
| n ≤ 50 | `O(n⁴)` | 6×10⁶ | 四维 DP、Floyd + 枚举 |
| n ≤ 100 | `O(n³)` | 10⁶ | **Floyd**、区间 DP、朴素 Dijkstra |
| n ≤ 500 | `O(n³)` | 1.25×10⁸ | 卡常的 O(n³)，或 O(n² log n) |
| n ≤ 1000 | `O(n²)` | 10⁶ | **二维 DP**、双重循环暴力 |
| n ≤ 5000 | `O(n²)` | 2.5×10⁷ | O(n²) 需卡常 |
| n ≤ 10⁵ | `O(n√n)` / `O(n log n)` | 3×10⁷ / 1.7×10⁶ | **排序、堆、树状数组、线段树、二分、STL map** |
| n ≤ 10⁶ | `O(n)` / `O(n log n)` | 10⁶ / 2×10⁷ | **线性筛、单调栈、双指针、前缀和、KMP** |
| n ≤ 10⁹ | `O(log n)` / `O(√n)` | 30 / 3×10⁴ | **快速幂、二分答案、数学公式、质因数分解** |
| n ≥ 10¹² | `O(log n)` / `O(1)` | — | **找规律、矩阵快速幂、数学推导** |

### 反过来用：从题面措辞推断解法

| 我看到题面写 | 我立刻想到 |
|---|---|
| `n ≤ 20` | **状压 DP 或暴力枚举子集**，出题人在明示 |
| `n ≤ 100` 且求最短路 | Floyd `O(n³)` 就够，别写 Dijkstra |
| `n ≤ 10⁵`，`m ≤ 2×10⁵` | 必须 `O(n log n)`，**任何 O(n²) 都会 TLE** |
| `n ≤ 10⁵`，有"区间修改+区间查询" | **线段树 / 树状数组 + 差分** |
| `n ≤ 10⁵`，有"第 k 大 / 最小化最大值" | **二分答案** |
| `n ≤ 10⁹`，求 `a^b mod p` | 快速幂 |
| **有"其中 X% 的数据满足 n ≤ …"** | **这是明示的部分分，立刻写暴力交上去** |
| 坐标都是整数 | **几何题全程用 `ll` 叉积，避免浮点** |

> ⚠️ 倒数第二条极其重要。CSP 题面里的"其中 X% 的数据满足 …"**不是废话，是出题人给你的送分提示**。

### 复杂度速算表（考场心算用）

| n | `O(n)` | `O(n log n)` | `O(n√n)` | `O(n²)` | `O(n³)` |
|---|---|---|---|---|---|
| 100 | 10² | 7×10² | 10³ | 10⁴ | 10⁶ |
| 1 000 | 10³ | 10⁴ | 3×10⁴ | 10⁶ | **10⁹ ⚠️** |
| 10 000 | 10⁴ | 1.3×10⁵ | 10⁶ | **10⁸ ⚠️** | 超时 |
| 100 000 | 10⁵ | 1.7×10⁶ | 3×10⁷ | 超时 | 超时 |
| 1 000 000 | 10⁶ | 2×10⁷ | 超时 | 超时 | 超时 |

**安全线：≤ 3×10⁷ 稳，≤ 10⁸ 勉强（1s 时限）。**
`map`/`set` 常数约为数组的 **5~10 倍**，估算要打折。

### 空间估算

- `int a[1000005]` = 4 MB；`ll a[1000005]` = 8 MB
- 二维 `int a[1005][1005]` = 4 MB；`int a[5005][5005]` = 100 MB ⚠️
- **线段树数组必须开 `4 * n`**
- CSP 空间限制常见 512 MB，**个别题 256 MB，看题面**

## 二、丢分六大原因（每次提交前扫一遍）

| # | 原因 | 症状 | 自查动作 |
|---|---|---|---|
| 1 | **long long 溢出** | 样例对，大数据全错 | 求和/乘积/计数是不是 `ll`？`1 << i` 该不该写 `1LL << i`？ |
| 2 | **题意理解偏差** | T3 拿到样例分就上不去 | 题面读 **3 遍**了吗？「若」「则」「同时」「不超过」「恰好」「保证」「优先」都圈了吗？ |
| 3 | **边界没处理** | 差 10~20 分 | n=1？n=0？空集？最大值？全相同？负数？重复元素？ |
| 4 | **输出格式错** | 0 分 | 空格还是换行？结尾要换行吗？大小写对吗？**逐字符比样例** |
| 5 | **TLE** | 大数据超时 | `sync_with_stdio(false)` 加了？用 `'\n'` 不是 `endl`？复杂度对吗？ |
| 6 | **`sort` 比较器写 `<=`** | **RE，整题 0 分** | 最后一级必须是 `<`！相等时返回 `true` 是未定义行为 |

## 三、C++ 语言层面的坑（考场高频翻车点）

### 输入输出

- [ ] `ios::sync_with_stdio(false); cin.tie(nullptr);` 之后**不能再混用 `scanf`/`printf`**
- [ ] 输出换行用 `'\n'`，**不要用 `endl`**（每次 flush，大量输出时慢很多）
- [ ] `cin >> n` 后接 `getline` 必须 `cin.ignore()`，否则读到空行
- [ ] 读到 EOF 用 `while (cin >> x)`，**不要用 `while (!cin.eof())`**（会多读一次）
- [ ] 大量输出攒到 `string` 里一次 `cout`，或用 `putchar`
- [ ] **交互题必须 `endl` 或 `fflush`**（唯一要用 endl 的场景）

### 数据类型

- [ ] **默认 `ll`**：`int` 上限约 2.1×10⁹，两个 10⁵ 相乘就爆
- [ ] `1 << 31` 是未定义行为 → 写 `1LL << 31`
- [ ] `ll c = a * b`（a、b 都是 int）→ 乘法在 int 范围内就已经溢出，要写 `1LL * a * b`
- [ ] `abs()` 对 `ll` 要用 `llabs()` 或 `std::abs`
- [ ] 浮点数**不要用 `==`**，用 `fabs(a-b) < EPS`；能用整数就别用浮点
- [ ] `acos`/`asin` 参数必须 `clamp` 到 [-1, 1]，否则返回 NaN
- [ ] C++ 的 `%` 对负数结果为负 → `(x % m + m) % m`

### 数组与容器

- [ ] **全局数组自动清零，局部数组不清零**（`int a[100]` 在函数里是随机值）
- [ ] 数组开多大：`n ≤ 10⁵` → 开 `100005`；线段树 → `4 * n`；树状数组 → `n + 2`
- [ ] `vector<bool>` **不是真容器**，不能取地址，性能差 → 用 `vector<int>` 或 `bitset`
- [ ] `v.size() - 1` 当 `v` 为空时是**巨大正数**（无符号溢出）→ 写 `i + 1 < v.size()`
- [ ] `erase` 迭代器后必须用返回值：`it = v.erase(it);`
- [ ] `map` 的 `operator[]` **会插入默认值** → 只读判断用 `find` / `count`
- [ ] `priority_queue` **默认是大根堆**；小根堆用 `greater<>`
- [ ] `priority_queue` 的比较器语义和 `sort` **相反**（返回 true 的优先级更低）
- [ ] `unordered_set` **没有 `lower_bound`**，要前驱后继必须用 `set`
- [ ] `unordered_map` 在 CSP 上**可能被卡哈希** → n ≤ 10⁵ 优先用 `map`
- [ ] `unique` 只去**相邻**重复，用前必须 `sort`
- [ ] `accumulate(all(v), 0)` 是 int 累加会溢出 → 写 `0LL`
- [ ] `next_permutation` 前必须 `sort`

### 函数与递归

- [ ] `sort` 比较器必须**严格弱序**（相等返回 `false`），写 `<=` 会 RE
- [ ] 递归深度 > 10⁴ 会**栈溢出**（考场栈约 8MB）→ 改迭代版或 BFS
- [ ] DFS 改迭代版时，**入栈就标记 `vis`**，不是出栈时标记
- [ ] 多组数据时，**全局数组必须在每组开头重置**
- [ ] 大对象传参要加 `const &`，否则拷贝超时
- [ ] 回溯的**撤销**不能忘

### 编译与环境

- [ ] 本地统一 `g++ -O2 -std=c++17 -DONLINE_JUDGE -Wall`
- [ ] 考场是 **Ubuntu 24.04 + g++ 13.2.0**，**不要用 C++20/23 特性**（concepts / ranges / `std::format`）
- [ ] `#include <bits/stdc++.h>` 在 g++ 下可用
- [ ] **不要依赖 `#pragma GCC optimize`**，先保证算法复杂度对
- [ ] 本地文件重定向要包在 `#ifndef ONLINE_JUDGE` 里
- [ ] 调试输出用 `cerr` 或包在 `#ifndef ONLINE_JUDGE`，否则交上去 WA

### T3 大模拟能力

**读题**

- [ ] 能在 3 遍阅读内把题面拆成编号规则（R1、R2、…）
- [ ] 会圈限定词：「若」「则」「同时」「不超过」「恰好」「至少」「保证」「优先」「否则」
- [ ] 会识别"**同时发生事件的优先级规则**"（CSP 最爱埋的坑）
- [ ] 读完后能**用自己的话复述题意**，并对照样例验证

**建模**

- [ ] 会先写 `struct` 列出所有状态量，**再**动手写逻辑
- [ ] 能正确选容器（`map` vs `unordered_map` vs `vector` vs `priority_queue`）
- [ ] 会把"操作"抽象成统一的 `struct Op { int type; ... }` 再排序处理
- [ ] 会写多关键字排序（逐级判断，**最后一级用 `<`**）

**实现**

- [ ] **分阶段实现**：每实现一条规则就用样例验证一次
- [ ] 300~500 行代码能一次写对（靠结构化：每条规则一个函数）
- [ ] 会主动造极端样例：空集、n=1、最大值、全相同、重复操作、非法输入
- [ ] 默认 `ll`；输出格式逐字符对照样例
- [ ] **卡住 20 min 会保存当前版本从头重写**（且重写前一定保存旧版本）

## 五、症状 → 病因速查表

| 症状 | 优先怀疑 |
|---|---|
| 样例就错 | 读题理解错 / 读入格式错 / 输出格式错 |
| 样例对，小数据对，大数据全错 | **`ll` 溢出** / 数组开小了 |
| 样例对，得 30~70 分卡住 | **边界情况没处理** / 特殊性质没考虑 |
| 得 0 分 | RE（比较器写 `<=`、数组越界、递归爆栈）/ 编译错误 / 输出格式完全错 |
| TLE | IO 没加速 / 用了 `endl` / `map` 该用数组 / 复杂度本身错 / SPFA 被卡 |
| MLE | 数组开太大 / 邻接矩阵存了 10⁵ 个点 / `map` 条目太多 |
| 有时对有时错 | **局部数组没初始化** / 多组数据没重置 / 未定义行为 |
| 本地对，提交错 | 本地文件重定向没去掉 / 用了 C++20 特性 / 编译器版本差异 |
| 几何题 WA | **80% 是精度不是算法**：EPS 够小吗？clamp 了吗？能用平方吗？输出 `-0.00` 了吗？ |
