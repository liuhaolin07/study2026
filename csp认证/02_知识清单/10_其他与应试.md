## 10.1 大模拟方法论 ★★★★★

> CSP T3 几乎从不考高级算法，考的是**工程能力**。练 20 道 T3 就能从 40 分稳定到 90+，
> 而同样的时间投在 T5 上可能只涨 10 分。**这是全场性价比最高的训练。**

### 四步法

#### 第 1 步：拆规则

题面读 **3 遍**，把每条规则编号写在草稿纸上：

```
R1: 输入 n 个操作，每个是 "insert x" / "delete x" / "query x"
R2: insert 时若 x 已存在，忽略
R3: delete 时若 x 不存在，输出 "error"
R4: 同一时刻的 delete 优先于 insert
R5: 输出总量可能很大，需要缓冲
```

**圈出所有限定词**：「若」「则」「同时」「不超过」「恰好」「至少」「保证」「优先」「否则」「除非」。
CSP 的坑 90% 藏在这些词里，尤其是 **R4 这类"同时发生怎么处理"**。

**读题时同步做两件事**：
- 在草稿上写"已知什么 / 求什么 / 输出格式"
- 对着样例验证自己的理解（样例是最好的题意检查器）

#### 第 2 步：定状态

**先把所有需要维护的量列出来，再选容器。不要边想边写代码。**

```cpp
struct State {
    // 列出所有状态量，每个都写注释说明含义和取值范围
    ll capacity;                 // 当前容量，范围 [0, C]
    ll last_refill;              // 上次恢复时间点
    vector<int> served;          // 已服务的事件编号
    map<string, int> counter;    // 名字 -> 出现次数
};
```

容器选型见 `02_数据结构.md` 2.13。

#### 第 3 步：排顺序

明确**事件的时间轴**：

- 事件有先后？→ 按时间 `sort`
- 同一时刻多个事件？→ **题目一定给了优先级规则，回去找**
- 多关键字排序时，比较器严格按题目给的优先级顺序写，**最后一级用 `<`**

```cpp
bool cmp(const Event& a, const Event& b) {
    if (a.t != b.t) return a.t < b.t;        // 第一关键字
    if (a.p != b.p) return a.p > b.p;        // 第二关键字
    return a.idx < b.idx;                    // ⚠️ 最后一级必须 <，不能 <=
}
```

#### 第 4 步：分阶段实现 + 逐样例验证

**每实现一条规则，就用样例验证一次。** 绝对不要 300 行写完再跑——调试成本是指数级的。

```cpp
// ❌ 反例：一个 300 行的 main
// ✅ 正例：每条规则一个函数
bool check_valid(const Op& op);          // 合法性校验
void rule_2_insert(const Op& op);
void rule_3_delete(const Op& op);
void process(const Op& op) {
    if (!check_valid(op)) return;
    switch (op.type) { /* 分派到各规则 */ }
}
```

好处：**每个函数可以单独用样例验证**，出问题时能二分定位。

### 大模拟失分三大原因

| 原因 | 症状 | 对策 |
|---|---|---|
| **题意理解偏差** | 样例都过不了 | 题面读 3 遍，圈限定词，**自己复述一遍题意**并对照样例 |
| **边界没处理** | 样例过，测试点丢 10~30 分 | 主动造极端样例：空集、n=1、最大值、全相同、重复操作、非法输入 |
| **数据类型溢出** | 小数据对，大数据全错 | **默认全用 `ll`**，尤其求和/乘积/计数 |

### 大模拟的"重写策略"

**卡住 20 分钟就保存当前版本，从头重写一遍。**

这不是浪费时间，是**最快的调试方式**。原因：
- 大模拟的 bug 往往是**设计层面**的（struct 设计不合理、状态维护顺序错），不是语法层面的
- 重写时你已经完全理解题意，第二遍通常 20 分钟就能写完
- 而调试一个 300 行的错误设计，可能要 1 小时还调不出来

⚠️ 重写前**一定要保存旧版本**（复制成一个新文件或注释掉），因为新版本可能还不如旧的。

### 配套练习

**W3 ~ W4 建议顺序**（按规则数量从少到多）：

```
画图(CSP 第6次 T2) → 节日(第4次 T2) → 字符串匹配(第2次 T2)
→ 路径解析(第7次 T3) → 集合竞价(第3次 T3) → 命令行选项(第1次 T3)
→ 模板生成系统(第5次 T3) → 文本处理(第10次 T3)
→ 权限查询(第9次 T3) → 炉石传说(第8次 T3) → 网络连接(2021-09 T3)
```

完整题单见 [`../03_真题题单/历年真题题单.md`](../03_真题题单/历年真题题单.md) 第四节。

### 每道 T3 做完必答

1. 我漏了哪条规则？为什么会漏？（没读到 / 读到了没理解 / 理解了实现时忘了）
2. 我在哪个边界上丢了分？
3. 我用了多少分钟？其中读题 / 建模 / 编码 / 调试各占多少？
4. 如果重写一遍，`struct` 会怎么设计得更清楚？
5. **这道题里"同时发生的事件"是怎么排序的？我一开始理解对了吗？**

## 10.2 非传统题型 ★★

CSP 传统题（规定输入输出）占绝大多数，但历年偶有其他题型。**认得出、不慌**就够了。

### ① 提交答案题

**形式**：给出输入数据文件，你只需提交输出结果文件，不提交程序。

**应对**：
- **不需要写正确的程序**，只需要产出答案
- 可以写**极慢的暴力**（跑 10 分钟也行），只要能出结果
- 可以**手算**小数据
- 可以写程序生成"看起来合理"的答案（部分分）
- ⚠️ 这类题的部分分**极其好拿**，别放弃

### ② 交互题

**形式**：程序与评测机交互，通过询问获取信息。

```cpp
// 典型流程
cout << "? l r" << endl;          // ⚠️ 交互题【必须用 endl 或 fflush】，否则评测机收不到
cout.flush();
int res; cin >> res;
// ...
cout << "! answer" << endl;
```

**应对**：
- **必须 `endl` 或手动 `fflush(stdout)`**——这是交互题唯一的坑，忘了就 0 分
- 询问次数通常有上限，用二分把次数压到 `O(log n)`
- 常见模型：猜数（二分）、找特殊元素（分治）、图的探索（并查集）

### ③ 补全代码题

**形式**：给出部分代码，你补全空缺部分。

**应对**：
- **先通读给出的代码**，理解变量含义和控制流
- 从上下文推断：空缺前后的代码在做什么
- 注意函数签名、返回类型、参数名

⚠️ CSP 目前**几乎不出这类题**（主要是 GESP/CSP-J 初赛的形式）。了解即可。

### ④ 通信题 / 多程序协作

极罕见，两个程序通过文件交换信息。**CSP 从未考过。**

## 10.3 部分分技巧 ★★★★★

### 部分分的五个来源

| 来源 | 怎么做 | 典型收益 |
|---|---|---|
| **样例数据** | 只要程序能跑、格式对，样例点就过了 | 5~15 分（白送） |
| **小数据暴力** | 题面写"其中 30% 的数据满足 n ≤ 100"→ 写 O(n²)/O(n³) | 20~40 分 |
| **特殊性质数据** | "保证图是一棵树" / "保证所有数互不相同" / "k = 1" → 特判 | 10~30 分 |
| **退化情形** | n = 1、n = 0、全相等、答案恒为 0 | 5~10 分 |
| **输出格式分** | 有些题只要求输出一个数，暴力枚举即可 | 10~20 分 |

### 10 分钟暴力挑战（**核心训练方法**）

找 T4/T5 的题，每道**只给自己 10 分钟**：

1. 读完题
2. 写出最朴素的暴力（不追求任何优化）
3. 编译通过、样例通过
4. 提交

**10 分钟内没交出去就算失败。** 这个训练的目的不是做对题，是练"快速产出能拿分的代码"。

### 暴力写法速查

| 题目形态 | 10 分钟内能写出的暴力 | 预期得分 |
|---|---|---|
| 求最优解（最大/最小） | 枚举所有方案，`next_permutation` 或 DFS | 20~40 |
| 区间查询 / 修改 | 直接模拟，每次操作 O(n) | 30~50 |
| 图上问题 | Floyd O(n³) 或每个点跑一遍 BFS | 30~50 |
| 计数问题 | DFS 枚举所有情况直接数 | 20~40 |
| 字符串问题 | O(n²) 枚举所有子串 | 30~50 |
| 完全没思路 | **特判 n=1、n=2，或写个能过样例的程序** | 5~15 |

> 最后一行不是玩笑。**完全不会做的题，写个能通过样例的程序交上去，也比 0 分强。**
> 5 分 × 2 题 = 10 分，这 10 分可能就是 340 和 350 的区别。

### 分层派发写法

```cpp
if (n <= 20) {
    solve_brute();          // 状压 / 全排列暴力，稳拿小数据分
} else if (n <= 2000) {
    solve_quadratic();      // O(n²) DP
} else {
    solve_optimal();        // 正解
}
```

**正解写不完就只留暴力分支交上去**——这是正确决策，不是失败。
而且因为 CSP **取最高分**，先交暴力完全零风险。

### 常见特殊性质特判

```cpp
// "k = 1" 时答案平凡
if (k == 1) { cout << trivial_answer << '\n'; return 0; }

// "所有数互不相同" 时可以省略去重逻辑
// "保证图是一棵树" 时可以用 DFS 代替最短路
// "n = 1" 时直接输出
if (n == 1) { cout << a[0] << '\n'; return 0; }

// 答案恒为 0 或恒为某个值的情况
if (all_same) { cout << 0 << '\n'; return 0; }
```

## 10.4 调试技巧 ★★★★★

### ① 二分定位（**最有效**）

程序输出错了，但不知道错在哪一行？

```cpp
// 在代码中间插入断言，二分缩小范围
assert(invariant_1());          // 如果这里挂，bug 在前半段
// ... 更多代码 ...
assert(invariant_2());          // 如果这里挂，bug 在这两句之间
```

或者更粗暴：**注释掉一半代码**，看输出是否变化，二分定位。

### ② 打印中间状态

```cpp
#ifndef ONLINE_JUDGE
#define DEBUG(x) cerr << #x << " = " << (x) << '\n'
#else
#define DEBUG(x)
#endif

DEBUG(cur_sum);
DEBUG(i);
```

⚠️ **调试输出必须用 `cerr` 或包在 `#ifndef ONLINE_JUDGE` 里**，否则交上去会 WA（输出多了东西）。

### ③ 手跑样例

**在纸上模拟程序对样例的执行过程**，一步一步写下变量值。
这比盯着代码看有效 10 倍，尤其对大模拟。

### ④ 造极端样例

程序样例过了但得分不高？**自己造数据**：

| 极端情况 | 为什么要测 |
|---|---|
| n = 1 | 边界，很多循环写错 |
| n = 0 | 空输入 |
| 所有元素相同 | 去重逻辑、比较器的 `<=` 问题 |
| 最大值 / 最小值 | 溢出 |
| 全负数 | 取模、绝对值 |
| 链状图 / 星状图 | 递归深度、算法退化 |
| 完全图 | 稠密图算法复杂度 |
| 重复元素很多 | 哈希冲突、multiset 用法 |

### ⑤ 用暴力对拍

见 10.5。

### ⑥ 常见 bug 速查表

| 症状 | 优先怀疑 |
|---|---|
| 样例就错 | 读题理解错 / 读入格式错 / 输出格式错 |
| 样例对，小数据对，大数据全错 | **`long long` 溢出** / 数组开小了 |
| 样例对，得 30~70 分卡住 | **边界情况没处理** / 特殊性质没考虑 |
| 得 0 分 | RE（比较器写 `<=`、数组越界、递归爆栈）/ 编译错误 / 输出格式完全错 |
| TLE | IO 没加速 / 用了 `endl` / `map` 该用数组 / 复杂度本身错 / SPFA 被卡 |
| MLE | 数组开太大 / 邻接矩阵存了 10⁵ 个点 / `map` 条目太多 |
| 有时对有时错 | **局部数组没初始化** / 多组数据没重置 / 未定义行为 |
| 本地对，提交错 | 本地文件重定向没去掉 / 用了 C++20 特性 / 编译器版本差异 |

## 10.5 对拍 ★★★

### 原理

写一个**一定正确的暴力**和一个**待验证的正解**，用随机数据反复比对。一旦不一致，那份数据就是**最小反例**。

### 三个文件

```cpp
// gen.cpp —— 随机数据生成器
#include <bits/stdc++.h>
using namespace std;
int main(int argc, char** argv) {
    srand(atoi(argv[1]));                      // 用命令行参数做种子，保证可复现
    int n = rand() % 10 + 1;                   // 小规模！暴力要能跑完
    cout << n << '\n';
    for (int i = 0; i < n; i++) cout << rand() % 100 << ' ';
    cout << '\n';
    return 0;
}

// brute.cpp —— 暴力（直白到不可能写错）
// sol.cpp   —— 正解（待验证）
```

### PowerShell 对拍脚本

```powershell
# 保存到 cmp.ps1，用法：.\cmp.ps1
$ErrorActionPreference = 'Continue'
g++ -O2 -std=c++17 gen.cpp -o gen.exe
g++ -O2 -std=c++17 brute.cpp -o brute.exe
g++ -O2 -std=c++17 sol.cpp -o sol.exe

for ($i = 1; $i -le 1000; $i++) {
    .\gen.exe $i | Out-File -Encoding ascii data.txt
    $r1 = Get-Content data.txt | .\brute.exe
    $r2 = Get-Content data.txt | .\sol.exe
    if ("$r1" -ne "$r2") {
        Write-Host "MISMATCH at seed $i"
        Write-Host "input:";  Get-Content data.txt
        Write-Host "brute: $r1"
        Write-Host "sol:   $r2"
        break
    }
}
Write-Host "done"
```

### 对拍的三条纪律

1. **暴力必须直白到不可能写错**——如果你不确定暴力对不对，对拍就没意义
2. **数据规模要小**（n ≤ 20），这样暴力能跑完，且更容易暴露边界 bug
3. **随机数据要包含极端情况**：全相同、递增、递减、全 0、全负数

### 考场能用对拍吗

**不能**（考场只有 4 小时，没有脚本环境）。但**练习时养成对拍习惯**，会让你对"我的正解到底对不对"有底，而不是靠感觉提交。

## 10.6 卡常与防 TLE ★★★★

### 第一优先级：确认复杂度对不对

**卡常只能救 2~3 倍的差距，救不了 100 倍。** 如果复杂度是 O(n²) 而 n = 10⁵，卡常没用，必须换算法。

### IO 优化（**最常见的 TLE 原因**）

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
// 输出用 '\n' 不用 endl
// 数据量 >= 1e6 时用 getchar 手写快读
// 大量输出时攒到 string 里一次性 cout，或用 putchar
```

### 常数优化

```cpp
// ① 数组代替 map/set（值域小时）
int cnt[100005];                    // 比 map<int,int> 快 10 倍以上

// ② vector 预分配
v.reserve(n);                       // 避免反复扩容拷贝

// ③ 循环里的重复计算提到外面
for (int i = 0; i < n; i++) {
    int sz = v.size();              // ✅
    // for (...; i < v.size(); ...) // ❌ 每次调用 size()
}

// ④ 二维数组按行访问（缓存友好）
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)     // ✅ 连续内存
// 反过来访问会频繁 cache miss，慢 5~10 倍

// ⑤ 矩阵乘法循环顺序 i-k-j（不是 i-j-k）

// ⑥ 用 += 代替 push_back 到 map
// ⑦ 位运算代替乘除 2 的幂：x * 2 -> x << 1（编译器一般会自动优化）

// ⑧ inline 小函数
inline int lowbit(int x) { return x & -x; }
```

### 编译选项

考场固定 `-O2 -DONLINE_JUDGE -std=c++17`，**不能改**。所以：
- ⚠️ **不要依赖 `#pragma GCC optimize("O3")`**——考场可能忽略，且可能引发诡异 bug
- ⚠️ 不要用 `-Ofast` 才正确的代码（依赖浮点重排）

### 复杂度降级（比卡常有效得多）

| 原复杂度 | 降级方法 |
|---|---|
| O(n²) → O(n log n) | 排序 + 二分 / 树状数组代替暴力统计 |
| O(n³) → O(n² log n) | 最内层用二分 / 预处理 |
| O(2ⁿ) → O(2^(n/2)) | **Meet in the Middle** |
| O(n²) → O(n√n) | 分块 |
| SPFA → Dijkstra | 换算法（SPFA 会被网格图卡） |
| `map` → 数组 | 值域小就用计数数组 |

```
   有 → 【立刻写对应的暴力，提交，锁定分数】
  ↓
③ 我能在 5 分钟内想出正解吗？
   能 → 写正解，提交
   不能 → 看 ④
  ↓
④ 这道题的类型是什么？
   大模拟   → 走四步法，限时 90 min，到点必须切走
   图论     → 查 06_图论.md 6.13 的建模套路
   DP       → 查 05_动态规划.md 5.14 的状态设计四手段
   数学     → 查 07_数学.md，先试打表找规律
   字符串   → 查 08_字符串.md 8.10 的选型表
   几何     → 坐标是整数吗？是 → 全程 ll 叉积
   看不出来 → 【写暴力 DFS 提交】，然后跳下一题
  ↓
⑤ 提交后看分数变化
   30 → 60：思路对，是边界/细节问题，继续调
   30 → 30：思路本身错了，回去重想或放弃
```

### 时间告急的处理

| 剩余时间 | 动作 |
|---|---|
| 60 min | 检查 T4/T5 是否都交了暴力。没交的**立刻写暴力** |
| 30 min | 停止思考正解。把所有没交的题都写上"能过样例的程序"交掉 |
| 15 min | **只确认提交记录，不改代码**（服务器开始拥堵） |
| 5 min | 停手。检查 5 题都有提交，且题目和代码对应 |

### 三个反直觉但正确的决策

1. **T3 到 90 分钟必须切走**，哪怕还差一点。因为 T4/T5 的暴力分（50~70 分）比 T3 的最后 20 分好拿
2. **T5 不要试图做出来**。目标就是 20 分的暴力分，多花的时间应该投给 T3
3. **完全不会的题也要提交**。一个能过样例的程序 = 5~15 分，白送
