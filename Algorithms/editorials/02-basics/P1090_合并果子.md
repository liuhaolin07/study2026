# P1090 [NOIP2004 提高组] 合并果子

- 专题:`02-basics` § 贪心(哈夫曼编码)
- 难度:普及-/普及

## 题意

n(n ≤ 10^4)堆果子,每次可以把任意两堆合并成一堆,代价为两堆之和。把所有果子合并成一堆,求最小总代价。

## 思路怎么来的

先小规模模拟找规律:果子 1, 2, 3。方案对比——
- 先合 1+2(代价 3),再合 3+3(代价 6),总计 9;
- 先合 2+3(代价 5),再合 5+1(代价 6),总计 11。

**小的先合并**更优。直观理解:每堆果子最终被"计费"的次数 = 它参与的合并次数。一堆越早被合并,后面每次合并都会带着它重复计费。所以让小的堆多承担合并次数、大的堆尽量晚合并。

严格的交换论证:若某次最优解合并的不是当前最小的两堆,把它们换成更小的两堆,总代价不增。这就是**哈夫曼树**的构造过程,本题即哈夫曼编码思想的模板题。

实现:每次取最小两堆 → 优先队列(小根堆)。合并出的新堆还要参与后续比较,塞回堆里。共合并 n-1 次。

## 复杂度

每次堆操作 O(log n),共 n-1 次合并,O(n log n)。

## 参考代码

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    priority_queue<ll, vector<ll>, greater<ll>> pq;   // 小根堆
    for (int i = 0; i < n; i++) {
        ll x; cin >> x;
        pq.push(x);
    }
    ll ans = 0;
    while (pq.size() > 1) {
        ll a = pq.top(); pq.pop();
        ll b = pq.top(); pq.pop();
        ans += a + b;
        pq.push(a + b);
    }
    cout << ans << '\n';
    return 0;
}
```

## 易错点

1. `priority_queue` 默认是大根堆,小根堆要写 `priority_queue<ll, vector<ll>, greater<ll>>`。
2. **合并结果要塞回堆里**,不是合并原数组前 k 小就完事——新堆的体重影响后续选择。
3. n = 1 时无需合并,答案 0,`while (pq.size() > 1)` 天然处理了这种情况。
4. 本题数据总和 ≤ 10^4 × 10^4 = 10^8 没爆 int,但养成求和用 ll 的习惯没坏处。
