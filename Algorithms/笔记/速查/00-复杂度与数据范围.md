# 速查:复杂度与数据范围反推算法

> 拿到题先看数据范围,再决定算法方向——这是最基本的反射,赛前扫一遍。

## 一、数据范围 → 算法对照

| 数据范围(n) | 大致复杂度预算 | 常见算法方向 |
|---|---|---|
| n ≤ 10~12 | O(n!·n) | 全排列爆搜 |
| n ≤ 20~24 | O(2^n) | 状压 DP、子集枚举、爆搜+剪枝 |
| n ≤ 24~40(值大) | O(2^(n/2)) | 折半搜索 meet in the middle |
| n ≤ 500 | O(n^3) | floyd、区间 DP、矩阵快速幂 |
| n ≤ 3000~7000 | O(n^2) | 朴素 DP、朴素图算法、双重循环贪心 |
| n ≤ 1e5 ~ 5e5 | O(n log n) 或 O(n√n) | 排序、二分、堆、线段树、分块、莫队 |
| n ≤ 1e7 | O(n) | 线性 DP、双指针、桶计数 |
| n ≥ 1e9(或 1e18) | O(log n) 或 O(1) | 数学结论、快速幂、矩阵快速幂、二分答案、exgcd |
| 值域 V ≤ 1e6 | 与 V 相关 | 桶、计数、权值线段树、同余最短路 |
| 是一棵树 | 通常 O(n log n) 以内 | 树形 DP、倍增 LCA、树上差分 |
| 是 DAG | O(n+m)~O(nm) | 拓扑序 DP |

- 多测题看**总规模**(如 `∑n ≤ 2e5`),不是单组。
- 两个变量的题(n、m 都 1e5)按乘积估:n·m ≤ 1e7 直接暴力,否则想办法只枚举一个。

## 二、运算量直觉

- 1 秒 ≈ 1e8~1e9 次简单运算(C++ O2);`n log n` 里 n=1e5 时 log≈17。
- `log2(1e18) ≈ 60`,所以"乘一次除二"类操作随便开。
- 一次取模 ≈ 十几次加法的开销,内层循环能省则省(见 `../易错点与调试.md`)。

## 三、实现层面的坑

- **递归深度**:深递归(1e5 层以上)可能爆栈(洛谷默认栈较小)。改 BFS、手写栈,或把 DFS 改成显式遍历(如倍增 LCA 用 BFS 求深度)。
- **数组大小**:无向图开 `2*m`、字符串开 `n+1`、差分数组开 `n+2`、多测清空用 `memset` 只清实际用的部分。
- **IO 规模**:1e6 个数以上用快读/`scanf`;`cin` 记得 `sync_with_stdio(false)`。
- **答案上界**:n=1e5 的方案数、路径和很容易超 int,默认 long long(见 `../易错点与调试.md` 溢出条)。

## 四、想不到算法时按此顺序自救

1. 数据范围能不能反推出复杂度?(对应上表)
2. 排序/二分/贪心试过了吗?
3. 能不能转成图论/DP 模型?(状态是什么?)
4. 有没有"部分分"可拿?先写暴力保底再优化。
5. 均摊/势能/离线,这些高级手段是不是题目在暗示"修改会被撤销"?
