# 比赛策略

> 单人 CF 与 ICPC 全真模拟两套打法。三人一机的分工/题板/复盘细节见 `../比赛/icpc/README.md`,本文件不重复,只补单人节奏与通用流程。

## 一、单题通用流程(所有比赛通用)

1. **读题三要素**:操作是什么 → 限制条件是什么 → 数据范围多大(反推复杂度,见 `速查/00`)。
2. **手推样例**:样例往往就是题意补充说明,推不通=题意还没懂。
3. **猜算法**:从数据范围反推方向;想 30~40 分钟没思路就看题解(平时)/换题(赛中)。
4. **写完先过样例**,再自造 1~2 个极端样例(n=1、全相同、最大值)。
5. 提交前过一遍 `易错点与调试.md` 的检查清单。

## 二、CF Div2 单人节奏

| 时间 | 目标 |
|---|---|
| 前 30 分钟 | A 必过(5~15 分钟),B 争取过;读题别贪快,A/B 常有坑在样例里 |
| 30~90 分钟 | C:通常是"一个观察 + 一个基础算法";观察不出来就先写暴力拿部分分 |
| 之后 | D 或 C 二选一攻坚,**单题卡 40 分钟就换**,标记回头 |
| 最后 20 分钟 | 绝不空手退场:把"最接近的题"的暴力/特判版交上去 |

- **罚时意识**:宁可先交一版再改,不要憋大招;但**本地先编译**消灭 CE。
- 错一次罚 10 分钟,`hack` 存在的比赛别赌极端写法。
- 每场结束记录:过题数、罚时、卡点(见 redo-list);**48 小时内 upsolve**(规则见根 README)。
- rating 波动正常,只看**三个月趋势**;连续两场同一类卡点 → 回专题补 3 题。

## 三、ICPC / 全真模拟(三人一机)

流程、分工、题板、最后 1 小时纪律全部按 `../比赛/icpc/README.md` 执行,这里只列赛场最值钱的三条:

1. **读题阶段全员产出**:每题 3 分钟内把"题意+数据范围+初步方向"写上题板,宁可写错方向也别留空白——读题比写代码更稀缺。
2. **40 分钟汇报制**:任何题卡 40 分钟必须报队,决定换人/换题/上暴力。队内没有"我快解出来了"这种私事。
3. **交题双人检查**:交之前另一人按检查清单过一遍(文件名、多测、溢出、输出格式);ICPC 罚时是全队时间。

### 英文题面读法

- 重点顺序:Statement → Input/Output 格式 → Constraints → 样例解释;Notes 常含隐藏约定。
- 固定生词积累到个人小本:distinct / strictly increasing / at most / modulo / 1-based / lexicographically 等。
- 长题干先找"问题问什么"那句(通常在最后加粗),再回头读操作。

## 四、赛前一天与当天

**前一天**
- 过一遍 `模板/` 目录结构和 `模板/contest.cpp`,确认能 30 秒内拼出一份可编译的赛场文件。
- `笔记/速查/` 七张表各扫一遍;`易错点与调试.md` 检查清单读一遍。
- 不做新题,只看错题本(redo-list 里没划掉的)。

**当天/赛前 10 分钟**
- 环境:编译器、对拍脚本目录、字典/纸笔就位;ICPC 按三人一机清单就位。
- 决定第一题策略:CF 直接 A;ICPC 全员通读。
- 心态:目标不是"全对",是"把会做的题都变成 AC"。

## 五、赛后(48 小时纪律)

1. rated 赛后当天:把每道没做出的题按"没思路 / 有思路没写出 / 写挂"分类记入 upsolve.md。
2. 48 小时内完成 upsolve,同样分类的题看题解后**关掉重写**。
3. 写挂的 → 查 `易错点与调试.md` 对应条目并补录;没思路的 → 记 redo-list,一周后重做。
4. 同类卡点出现第二次 → 对应专题加练 3 题(根 README 铁律)。
